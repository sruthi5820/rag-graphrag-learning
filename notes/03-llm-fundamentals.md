
# Lesson 3: LLM Fundamentals and Transformers

## 3.1 What Is an LLM?

LLM stands for **Large Language Model**.

A Large Language Model is an AI model trained on large amounts of text to understand and generate human-like language.

An LLM predicts the next token based on the preceding context and patterns learned during training. It repeats this process to generate a sequence of tokens that forms a response.

### Examples of LLM Tasks

- Answering questions.
- Summarizing documents.
- Generating text and explanations.
- Translating languages.
- Extracting structured information.
- Writing and explaining code.
- Answering questions using retrieved documents.

### Examples of LLMs

- GPT models.
- Google Gemini models.
- Meta Llama models.
- Mistral models.
- Qwen models.
- Gemma models.

### Simple Example

**Input:**

What is the capital of India?

**Possible output:**

The capital of India is New Delhi.

### How Does an LLM Work?

1. Receives the input prompt.
2. Converts the input text into tokens.
3. Processes the tokens using its neural network.
4. Predicts the next token.
5. Repeats token generation until the response is complete or a stopping limit is reached.
6. Returns the generated response.

### Important Point

An LLM does not automatically know the latest information or the contents of private documents. Its answers depend on its training, the prompt, any supplied context, and the tools or information available to it.

## 3.2 What Is a Token?

A **token** is a unit of text processed by a language model.

A token can be:

- A complete word.
- Part of a word.
- A punctuation mark.
- A number or symbol.
- Another text unit defined by the tokenizer.

A tokenizer converts text into tokens according to the rules of a particular model.

### Example

Input text:

```text
Retrieval-Augmented Generation
```

A tokenizer might split this text into several tokens. The exact tokenization depends on the model and its tokenizer.

Do not assume that one word always equals one token.

### Why Are Tokens Important?

Tokens are important because they affect:

1. **Context window:** How much input and output the model can handle in one request.
2. **Input limit:** How much text can be sent to the model.
3. **Output limit:** How many tokens the model can generate.
4. **Inference cost:** Many hosted LLM services calculate usage based on input and output tokens.
5. **Performance:** Longer inputs generally require more processing.

### Tokens in RAG

A RAG application may send the following information to an LLM:

- System instructions.
- User question.
- Retrieved document chunks.
- Conversation history.
- Other formatting instructions.

All this information contributes to the input token count.

If too much information is included, the application may exceed the model's context window.

### Key Learning

Tokens are the basic text units that a language model processes and generates.

## 3.3 What Is a Transformer?

A **transformer** is a neural network architecture designed to process sequences of data using attention mechanisms.

Transformers are widely used in modern language models because they can learn relationships between different parts of a sequence.

### Why Were Transformers Important?

Traditional sequence-processing approaches often processed information sequentially. Transformer architectures introduced attention mechanisms that allow the model to relate different tokens in the input efficiently.

This helped enable the development of powerful language models.

### Main Components of a Transformer

#### 1. Tokenization

The input text is divided into tokens.

Example:

```text
RAG retrieves documents.
```

The tokenizer converts this sentence into token IDs.

#### 2. Embeddings

Token IDs are mapped to numerical vectors that represent tokens in a form the neural network can process.

These internal token representations are not the same thing as document embeddings generated by a separate embedding model for semantic search.

#### 3. Positional Information

The model needs information about token positions and sequence order.

Transformer architectures use different methods to represent or incorporate positional information.

#### 4. Attention Mechanism

Attention helps the model determine which other tokens are relevant when processing a particular token.

For example:

```text
The dog chased the ball because it was moving.
```

Understanding the word "it" requires considering other words in the sentence. Attention helps the model learn relationships between tokens.

#### 5. Neural Network Layers

The transformer processes token representations through neural network layers to build contextual representations.

#### 6. Output Prediction

For a generative language model, the processed representation is used to calculate probabilities for possible next tokens.

The model selects or samples a token according to its generation settings and repeats the process.

### Simplified Transformer Workflow

```text
Input Text
    |
    v
Tokenizer
    |
    v
Token IDs
    |
    v
Token Representations
    |
    v
Transformer Layers
(Attention + Neural Networks)
    |
    v
Next-Token Prediction
    |
    v
Generated Tokens
    |
    v
Output Text
```

### What Is Attention?

Attention is a mechanism that allows a model to weigh the relevance of different tokens when processing a sequence.

It helps the model learn contextual relationships instead of treating each token as completely independent.

### What Is Self-Attention?

Self-attention allows tokens in a sequence to interact with other tokens in that sequence.

For example, in the sentence:

```text
The student opened the book because it was interesting.
```

Self-attention can help the model learn relationships between "it" and other words in the sentence.

The actual interpretation depends on the surrounding context and what the model learned during training.

### Key Learning

A transformer uses attention and neural network layers to process token relationships and learn contextual representations.

## 3.4 Embedding Model vs Generative LLM

Embedding models and generative LLMs perform different roles in a typical RAG system.

### Embedding Model

An embedding model converts text into a numerical vector.

These vectors represent aspects of the text's meaning and can be compared to find semantically related content.

**Example use cases:**

- Semantic search.
- Document retrieval.
- Finding similar questions.
- Clustering related documents.
- Retrieving relevant chunks in a RAG application.

### Generative LLM

A generative LLM generates or transforms text based on its input, instructions, learned parameters, and supplied context.

**Example use cases:**

- Answering questions.
- Summarizing retrieved documents.
- Explaining information.
- Combining relevant information into a response.
- Generating structured output.

### Comparison Table

| Feature | Embedding Model | Generative LLM |
|---|---|---|
| Main purpose | Represent text as vectors | Generate or transform content |
| Typical output | Numerical vector | Text or structured output |
| Main RAG role | Retrieve relevant information | Generate the final answer |
| Common use | Semantic similarity search | Question answering |
| Input | Text or other supported data | Prompt, instructions and context |
| Output example | `[0.12, -0.08, 0.41, ...]` | "RAG combines retrieval and generation." |

Some model families support multiple tasks. However, embedding generation and answer generation remain distinct operations in a typical RAG pipeline.

### Example in RAG

Question:

```text
How can I reset my password?
```

The embedding model converts the question into a vector.

The retrieval system compares that vector with document vectors and finds relevant passages.

The generative LLM receives the question and retrieved passages and produces an answer.

### Key Learning

The embedding model helps find relevant information. The generative LLM uses the question and available context to generate a response.

## 3.5 What Is Context in an LLM?

**Context** is the information supplied to a model for a particular generation request.

Context may include:

- System instructions.
- User questions.
- Conversation history.
- Retrieved documents.
- Examples.
- Tool results.
- Formatting requirements.

The model uses this information when generating its response.

### Example of an LLM Prompt

```text
System instruction:
Answer using the provided context.
If the answer is not supported by the context, say you do not know.

Retrieved context:
RAG combines information retrieval with language generation.

Question:
What does RAG combine?

Answer:
```

Possible answer:

```text
RAG combines information retrieval with language generation.
```

### What Is a Context Window?

The context window is the amount of token information a model can process in a single request, including applicable input and generated output.

The exact limits depend on the model and serving configuration.

### Why Does Context Matter in RAG?

A RAG application retrieves relevant document chunks and includes them in the LLM prompt.

Good context can help the model produce more relevant, specific, and evidence-based answers.

Poor context can lead to:

- Irrelevant answers.
- Missing information.
- Confusing responses.
- Unsupported claims.
- Exceeding the context window.

### Important Point

Providing context does not guarantee a correct answer. The model may misunderstand or ignore information, so RAG applications need appropriate retrieval, instructions, citations, and evaluation.

## 3.6 Important LLM Settings

LLM settings influence how the model generates a response.

### 1. Temperature

Temperature controls the randomness of token selection during generation.

- Lower temperature generally produces more predictable outputs.
- Higher temperature generally allows more varied outputs.

Example:

A lower temperature may be useful for a support chatbot that needs consistent answers.

A higher temperature may be useful for creative writing.

Temperature does not guarantee factual accuracy.

### 2. Maximum Output Tokens

This setting limits the number of tokens generated in the response.

For example, a small output limit may cause a long answer to stop before all details are included.

The exact setting name depends on the model API.

### 3. Context Window

The context window determines how much input and output token information the model can handle in one request.

The context window is model-dependent and may also be constrained by the serving system.

### 4. System Instruction

A system instruction defines the model's role, behavior, and constraints.

Example:

```text
You are a helpful technical assistant.
Answer clearly and use simple language.
If the supplied context does not support an answer, say so.
```

System instructions help guide behavior but do not guarantee perfect compliance.

### 5. Streaming

Streaming returns generated output incrementally rather than waiting for the complete response.

Without streaming:

```text
Send question
      |
      v
Wait for complete answer
      |
      v
Display answer
```

With streaming:

```text
Send question
      |
      v
Generate first token
      |
      v
Display partial answer
      |
      v
Continue displaying tokens
      |
      v
Complete answer
```

Streaming can improve the perceived responsiveness of a chatbot, although it does not necessarily reduce the total generation time.

### 6. Top-p

Top-p, also called nucleus sampling, controls token selection by considering a set of likely next tokens whose cumulative probability reaches a specified threshold.

It is another generation setting that can influence output variability.

Not every API exposes the same parameters, and some serving systems recommend changing temperature or top-p rather than both together.

## 3.7 How an LLM Fits into a RAG System

RAG stands for **Retrieval-Augmented Generation**.

It combines information retrieval with language generation.

### RAG Workflow

```text
User Question
      |
      v
Question Embedding
      |
      v
Vector Database Search
      |
      v
Retrieve Relevant Chunks
      |
      v
Build Prompt
(Instructions + Question + Context)
      |
      v
Generative LLM
      |
      v
Generated Answer
      |
      v
Answer with Citations
```

### Responsibilities of Each Component

**Embedding model**
- Converts the question into a vector.
- Helps locate semantically related documents.

**Vector database or retrieval system**
- Stores or searches document representations.
- Returns relevant document chunks.

**Prompt construction**
- Combines instructions, the question, and retrieved context.

**Generative LLM**
- Uses the supplied information to generate the response.

**Citation handling**
- Connects claims in the answer to the supporting document chunks or source URLs.
- Helps users verify where the information came from.

Citation quality depends on the application correctly tracking the sources associated with retrieved content.

### Example

Suppose a company has a private document explaining its leave policy.

Question:

```text
How many days of annual leave are available?
```

A general LLM might not know the company's specific policy.

A RAG application retrieves the relevant policy passage and supplies it to the LLM.

The LLM then generates an answer based on that passage, and the application can include a citation to the source document.

### Key Learning

Retrieval supplies relevant information. The LLM generates a natural-language answer using the question, instructions, and retrieved context.

Use a locally available or hosted LLM.

Task:
- Send a simple question.
- Print the generated response.
- Observe how the model responds.


Send the same question with two different system instructions.

Instruction A:

```text

```

Instruction B:


Generate an answer using a small output limit, then increase the limit.

Ask a question that requires information from a document, but do not provide that document.

```text

```

First, ask the LLM without supplying the policy.

Next, provide a sample leave-policy document as context and ask the same question.

Compare the two answers.

**Goal:** Understand how retrieved context can help answer organization-specific questions.

Compare a normal LLM request with a streaming request if your model API supports both.

Observe when the first part of the answer appears and when generation finishes.

**Goal:** Understand the difference between complete-response delivery and incremental delivery.

## 3.9 Common Misconceptions

### Misconception 1: An LLM always knows the correct answer.

**Correction:** An LLM can produce incorrect or unsupported information. Its responses must be evaluated, especially for important tasks.

### Misconception 2: One word always equals one token.

**Correction:** A word may correspond to one token or several tokens, depending on the tokenizer.

### Misconception 3: An embedding model and a generative LLM are the same thing.

**Correction:** In a typical RAG system, the embedding model supports retrieval while the generative LLM produces the answer.

### Misconception 4: Adding documents to a vector database automatically teaches the LLM those documents.

**Correction:** The application retrieves relevant chunks and supplies them to the LLM at query time. The model's parameters are not automatically updated.

### Misconception 5: A prompt guarantees factual accuracy.

**Correction:** Instructions can guide the model but cannot guarantee that every answer will be correct.

### Misconception 6: A larger context window always produces better answers.

**Correction:** More context can help, but irrelevant, redundant, or poorly selected information can reduce answer quality and increase processing requirements.

## 3.10 Interview Questions and Answers

### Q1. What is an LLM?

An LLM is an AI model trained to process and generate language. Generative LLMs commonly produce text by predicting subsequent tokens.

### Q2. What is a token?

A token is a unit of text processed by a language model. It may represent a word, part of a word, punctuation, or another text unit.

### Q3. What is a transformer?

A transformer is a neural network architecture that uses attention mechanisms and neural network layers to process relationships between tokens.

### Q4. What is self-attention?

Self-attention allows tokens in a sequence to consider information from other tokens in that sequence.

### Q5. What is the difference between an embedding model and a generative LLM?

An embedding model converts text into numerical vectors for tasks such as semantic search. A generative LLM generates or transforms text.

### Q6. What is a context window?

A context window is the amount of token information a model can process in a single request, including applicable input and generated output.

### Q7. What is temperature?

Temperature influences randomness during token selection. Lower values generally produce more predictable outputs, while higher values generally allow more variation.

### Q8. What is streaming?

Streaming delivers generated output incrementally, allowing users to see parts of an answer before generation finishes.

### Q9. Why does RAG need an LLM?

The LLM uses the user's question, instructions, and retrieved information to generate a readable answer.

### Q10. Does RAG train the LLM every time a document is retrieved?

No. In a typical RAG system, documents are retrieved and added to the prompt at query time. This does not automatically update the LLM's learned parameters.

### Q11. Why can an LLM hallucinate?

A model can generate plausible-sounding information that is incorrect or unsupported. This can happen even when the model has been given instructions or context.

### Q12. How can RAG improve an LLM's answers?

RAG can provide relevant external information at query time, helping the model answer questions using documents that may not be included in its training data.

## 3.11 Key Learning Summary

- An LLM is an AI model that processes and generates language.
- A token is a unit of text processed by the model.
- A transformer uses attention and neural network layers to process token relationships.
- An embedding model converts text into vectors for semantic retrieval.
- A generative LLM generates or transforms text.
- Context includes instructions, questions, conversation history, and retrieved information.
- Temperature, output limits, context windows, and streaming affect model behavior or response delivery.
- RAG retrieves external information and supplies it to the LLM at query time.
- Retrieval, citations, and evaluation help improve the reliability and traceability of RAG answers.

**Final takeaway:** The LLM is the generation component of a typical RAG system. Retrieval supplies relevant information, and the LLM uses that information to produce an answer. Neither retrieval nor prompting alone guarantees factual accuracy.
